# DaCong 项目架构总览

> 版本：v1.0  
> 更新日期：2026-04-17  
> 架构风格：Clean Architecture + SOLID 原则

---

## 1. 项目概述

DaCong（大聪明）是一个 AI 工具决策助手平台，帮助用户快速找到最适合的 AI 工具。

### 1.1 核心价值
- **场景化推荐**：根据使用场景（写代码、做视频、做图片）推荐最佳工具
- **详细对比**：提供工具的优缺点、价格、访问方式等详细信息
- **精选周报**：每周精选 AI 工具和新闻

### 1.2 技术栈
- **前端**：Flutter 3.x (Web + iOS + Android)
- **后端**：Supabase Edge Functions (TypeScript + Deno)
- **数据库**：PostgreSQL (Supabase)
- **爬虫**：Python 3.11 + Scrapy
- **AI生成**：Claude 3.5 Sonnet API

## 3. 模块架构详解

### 3.1 爬虫模块 (dacong-spider/)

**架构风格**：面向对象 + 策略模式 + 工厂模式

```
┌─────────────────────────────────────────────────────────┐
│                    接口层 (Interfaces)                    │
│  IDataSource | IDataProcessor | IDataStorage | ...      │
└─────────────────┬───────────────────────────────────────┘
                  │ implements
┌─────────────────▼───────────────────────────────────────┐
│                    基类层 (Base Classes)                 │
│  BaseSpider | DataValidator | RetryHandler             │
└─────────────────┬───────────────────────────────────────┘
                  │ extends
┌─────────────────▼───────────────────────────────────────┐
│                  具体实现层 (Concrete)                    │
│  GitHubSpider | HuggingFaceSpider | OpenRouterSpider   │
│  RedditSpider | HackerNewsSpider                        │
└─────────────────────────────────────────────────────────┘
```

**SOLID 原则应用**：
- ✅ **SRP**：每个爬虫只负责一个数据源
- ✅ **OCP**：新增爬虫无需修改现有代码
- ✅ **LSP**：所有爬虫可以替换 BaseSpider
- ✅ **ISP**：接口小而专注（8个独立接口）
- ✅ **DIP**：依赖抽象接口，使用依赖注入

**关键设计模式**：
- **模板方法模式**：BaseSpider 定义执行流程
- **策略模式**：不同爬虫是不同策略
- **工厂模式**：SpiderFactory 创建实例
- **注册表模式**：SpiderRegistry 管理爬虫

**文件结构**：
```
dacong-spider/
├── core/
│   ├── interfaces.py          # 8个核心接口
│   ├── base.py               # BaseSpider + 工具类
│   ├── factory.py            # SpiderFactory
│   └── db.py                 # 数据库连接
├── spiders/
│   ├── github_spider.py      # GitHub爬虫
│   ├── huggingface_spider.py # HuggingFace爬虫
│   ├── openrouter_spider.py  # OpenRouter爬虫
│   ├── reddit_spider.py      # Reddit爬虫
│   └── hackernews_spider.py  # HackerNews爬虫
├── schedulers/
│   └── scheduler.py          # APScheduler定时任务
├── tests/
│   └── test_*.py            # 单元测试
└── docs/
    ├── ARCHITECTURE.md       # 架构文档
    └── CLASS_DIAGRAM.md      # 类图
```

### 3.2 后端API模块 (dacong-api/)

**架构风格**：分层架构 + DDD (Domain-Driven Design)

```
┌─────────────────────────────────────────────────────────┐
│                  API Layer (Edge Functions)              │
│  get-recommendations | get-content-detail | ...         │
└─────────────────┬───────────────────────────────────────┘
                  │ uses
┌─────────────────▼───────────────────────────────────────┐
│                  Service Layer (Business Logic)          │
│  ContentService | RecommendationService | ...           │
└─────────────────┬───────────────────────────────────────┘
                  │ uses
┌─────────────────▼───────────────────────────────────────┐
│              Repository Layer (Data Access)              │
│  IContentRepository → SupabaseContentRepository         │
└─────────────────┬───────────────────────────────────────┘
                  │ operates on
┌─────────────────▼───────────────────────────────────────┐
│                  Domain Layer (Entities)                 │
│  Content | Recommendation | UserFeedback                │
└─────────────────────────────────────────────────────────┘
```

**SOLID 原则应用**：
- ✅ **SRP**：每个服务只负责一个业务领域
- ✅ **OCP**：通过接口实现对扩展开放
- ✅ **LSP**：所有仓储实现可以无缝替换
- ✅ **ISP**：接口小而专注（3个独立仓储接口）
- ✅ **DIP**：服务层依赖仓储接口，不依赖具体实现

**关键设计模式**：
- **Repository 模式**：隔离数据访问逻辑
- **Service 模式**：封装业务逻辑
- **DTO 模式**：数据传输对象
- **依赖注入**：Container 管理依赖

**文件结构**：
```
dacong-api/supabase/functions/
├── _shared/
│   ├── domain/
│   │   ├── Content.ts           # 内容实体
│   │   ├── Recommendation.ts    # 推荐实体

│   │   └── *Request.ts                     # 请求验证
```

## 4. 数据流设计

### 4.1 推荐内容数据流

```
1. 爬虫采集
   GitHub/HF/OpenRouter → raw_data 表

2. AI生成
   raw_data → Claude API → generated_content 表

3. 人工审核
   generated_content → 审核通过 → published_content 表

4. 客户端展示
   Flutter → API → published_content → 用户
```

### 4.2 用户反馈数据流

```
1. 用户操作
   Flutter UI → SubmitFeedback Use Case

2. API处理
   Edge Function → FeedbackService → Repository

3. 数据存储
   user_feedback 表 + 更新 published_content 统计

4. 实时更新
   BLoC 监听 → UI 自动刷新
```

## 5. SOLID 原则总结

### 5.1 单一职责原则 (SRP)

**爬虫模块**：
- ✅ `GitHubSpider` 只负责 GitHub 数据采集
- ✅ `DataValidator` 只负责数据验证
- ✅ `RetryHandler` 只负责重试逻辑

**后端模块**：
- ✅ `ContentService` 只负责内容业务逻辑
- ✅ `SupabaseContentRepository` 只负责数据访问
- ✅ `Content` 实体只包含内容相关属性和行为

**前端模块**：
- ✅ `GetRecommendations` Use Case 只负责获取推荐
- ✅ `RecommendationBloc` 只负责推荐状态管理
- ✅ `RecommendationCard` 只负责推荐卡片展示

---

### 5.2 开闭原则 (OCP)

**爬虫模块**：
- ✅ 新增爬虫：继承 `BaseSpider`，无需修改现有代码
- ✅ 新增数据源：实现 `IDataSource` 接口

**后端模块**：
- ✅ 新增数据源：实现 `IContentRepository` 接口
- ✅ 新增业务逻辑：扩展 `ContentService`

**前端模块**：
- ✅ 新增功能：创建新的 Use Case
- ✅ 新增页面：创建新的 BLoC 和 Page

---

### 5.3 里氏替换原则 (LSP)

**爬虫模块**：
- ✅ 所有爬虫都可以替换 `BaseSpider`
- ✅ 所有存储实现都可以替换 `IDataStorage`

**后端模块**：
- ✅ `SupabaseContentRepository` 可以替换为 `MockContentRepository`
- ✅ 所有仓储实现都遵循接口契约

**前端模块**：
- ✅ `ContentRepositoryImpl` 可以替换为 `MockContentRepository`
- ✅ 测试时可以轻松 Mock 所有依赖

---

### 5.4 接口隔离原则 (ISP)

**爬虫模块**：
- ✅ 8个独立接口，每个接口只定义相关操作
- ✅ `IDataSource` 只定义数据获取方法
- ✅ `IDataStorage` 只定义存储方法

**后端模块**：
- ✅ 3个独立仓储接口，职责清晰
- ✅ `IContentRepository` 只定义内容相关操作
- ✅ `IFeedbackRepository` 只定义反馈相关操作

**前端模块**：
- ✅ 每个 Repository 接口只定义相关操作
- ✅ `IContentRepository` 不包含推荐相关方法
- ✅ `IScenarioRepository` 不包含内容相关方法

---

### 5.5 依赖倒置原则 (DIP)

**爬虫模块**：
- ✅ `BaseSpider` 依赖 `IDataStorage` 接口，不依赖具体实现
- ✅ 使用依赖注入传递具体实现

**后端模块**：
- ✅ `ContentService` 依赖 `IContentRepository` 接口
- ✅ 使用 `Container` 管理依赖关系

**前端模块**：
- ✅ `GetRecommendations` Use Case 依赖 `IScenarioRepository` 接口
- ✅ 使用 `get_it` + `injectable` 自动注入依赖

| **Facade 模式** | 简化复杂接口 | `dacong-api/_shared/services/` |

### 6.3 行为型模式

| 模式 | 应用场景 | 位置 |
