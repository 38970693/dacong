# 爬虫设计文档

## 1. 设计原则

1. **只写原始数据** — 爬虫不计算、不做业务逻辑，只负责采集和去重后写入 raw 表
2. **严格遵守 robots.txt** — 优先使用官方 API
3. **幂等写入** — 同一数据重复抓取时覆盖而非堆积
4. **异常隔离** — 单个爬虫出错不影响其他爬虫
5. **可追溯** — 所有操作写入日志，便于排查

## 2. 数据源

| 项目 | 说明 |
|------|------|
| URL | https://github.com/trending |
| 数据 | AI/ML 相关仓库的 star、fork 数 |
| 写入表 | model_raw_metrics |
| 爬取频率 | 每小时 |
| 技术方案 | GitHub REST API（推荐） + HTML 解析（备选） |

**GitHub API 示例：**
```python
# 搜索 AI 相关仓库
GET https://api.github.com/search/repositories
  ?q=language:Python+ML+OR+AI+OR+deep-learning
  &sort=stars
  &per_page=100
```

## 3. 去重策略

### 3.1 模型去重

根据 `source + model_name` 组合判断是否重复：
```sql
INSERT INTO model_raw_metrics (model_id, source, metric_type, metric_value, fetched_at)
VALUES ($1, $2, $3, $4, $5)
ON CONFLICT (model_id, source) 
DO UPDATE SET 
  metric_value = EXCLUDED.metric_value,
  fetched_at = EXCLUDED.fetched_at;
```

### 3.2 快讯去重

24 小时内的 `source + title` 组合去重：
```sql
DELETE FROM hot_news_raw 
WHERE source = $1 
  AND title = $2 
  AND fetched_at > now() - interval '24h';
```

## 4. 日志与监控

### 4.1 日志格式
```
2026-04-15 14:00:00 [INFO] github_trending: Fetched 50 repos, 3 new
2026-04-15 14:00:00 [INFO] github_trending: Wrote 3 rows to model_raw_metrics
2026-04-15 14:15:00 [WARN] hackernews: Rate limited, retry in 60s
2026-04-15 14:15:00 [ERROR] producthunt: Connection timeout
```

### 4.2 监控指标
- 每次爬取：成功/失败/去重数
- 长期：各数据源更新覆盖率

## 5. 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| 网络超时 | 指数退避重试（最多3次） |
| Rate Limit | 等待指定时间后重试 |
| 解析失败 | 记录日志、跳过该条、继续其他 |
| 写入失败 | 记录日志、告警、不重试（幂等性保证不堆积） |
