# 安全策略

## 概述

本文档定义 DaCong 项目的安全策略，包括安全目标、责任分工、安全标准和合规要求。

## 安全目标

### 核心目标

1. **数据保护**: 保护用户数据不被未授权访问、泄露或篡改
2. **服务可用**: 确保服务 99.9% 可用性，抵御 DDoS 和其他攻击
3. **合规性**: 符合 GDPR、个人信息保护法等法规要求
4. **快速响应**: 严重安全事件 24 小时内响应和修复

### 安全指标

| 指标 | 目标值 | 当前值 |
|------|--------|--------|
| 高危漏洞修复时间 | < 24 小时 | - |
| 中危漏洞修复时间 | < 7 天 | - |
| 安全扫描覆盖率 | 100% | 100% |
| 依赖漏洞修复率 | > 95% | - |
| 安全培训覆盖率 | 100% | - |

## 安全标准

### 认证和授权

#### 密码策略

- **最小长度**: 8 个字符
- **复杂度**: 必须包含大小写字母、数字和特殊字符
- **过期时间**: 90 天（可选）
- **历史限制**: 不能重复最近 5 次使用的密码
- **加密算法**: bcrypt (cost factor >= 12) 或 Argon2

#### 会话管理

- **JWT 过期时间**: 24 小时
- **Refresh Token 过期时间**: 30 天
- **密钥长度**: >= 256 位
- **密钥轮换**: 每 90 天
- **会话固定防护**: 登录后重新生成 session ID

#### 多因素认证 (MFA)

- **管理员账户**: 强制启用 MFA
- **普通用户**: 可选启用 MFA
- **支持方式**: TOTP (Google Authenticator)、SMS

### 数据保护

#### 敏感数据分类

| 级别 | 数据类型 | 保护措施 |
|------|---------|---------|
| 高度敏感 | 密码、支付信息、身份证号 | 加密存储、加密传输、访问审计 |
| 敏感 | 手机号、邮箱、地址 | 加密存储、访问控制 |
| 一般 | 用户名、昵称、头像 | 访问控制 |
| 公开 | 公开内容、统计数据 | 无特殊要求 |

#### 加密标准

**传输加密**:
- TLS 1.3 (最低 TLS 1.2)
- 禁用弱加密套件
- HSTS 强制 HTTPS

**存储加密**:
- AES-256-GCM
- 密钥存储在 KMS 或 Vault
- 定期密钥轮换

**数据库加密**:
- 透明数据加密 (TDE)
- 列级加密（敏感字段）
- 备份加密

### 输入验证

#### 验证原则

1. **白名单优于黑名单**: 定义允许的输入，而不是禁止的输入
2. **服务端验证**: 永远不要只依赖客户端验证
3. **类型检查**: 验证数据类型和格式
4. **长度限制**: 限制输入长度，防止 DoS

#### 常见漏洞防护

**SQL 注入**:
```typescript
// ❌ 错误: 字符串拼接
const query = `SELECT * FROM users WHERE id = ${userId}`;

// ✅ 正确: 参数化查询
const query = supabase
  .from('users')
  .select('*')
  .eq('id', userId);
```

**XSS 防护**:
```typescript
// ❌ 错误: 直接插入 HTML
element.innerHTML = userInput;

// ✅ 正确: 转义 HTML
element.textContent = userInput;
// 或使用 DOMPurify
element.innerHTML = DOMPurify.sanitize(userInput);
```

**CSRF 防护**:
- 使用 CSRF Token
- SameSite Cookie 属性
- 验证 Origin/Referer 头

### API 安全

#### 认证

- 所有 API 端点必须认证（除公开端点）
- 使用 Bearer Token (JWT)
- Token 在 Authorization 头中传递

#### 授权

- 基于角色的访问控制 (RBAC)
- 最小权限原则
- 资源级权限检查

#### 限流

| 端点类型 | 限制 |
|---------|------|
| 登录 | 5 次/分钟/IP |
| 注册 | 3 次/小时/IP |
| API 调用 | 100 次/分钟/用户 |
| 搜索 | 20 次/分钟/用户 |

#### 安全头

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Strict-Transport-Security: max-age=31536000; includeSubDomains
Content-Security-Policy: default-src 'self'
```

### 日志和监控

#### 日志记录

**必须记录**:
- 认证事件（登录、登出、失败尝试）
- 授权失败
- 敏感操作（数据修改、删除）
- 系统错误和异常

**禁止记录**:
- 密码（明文或加密）
- JWT Token
- 信用卡号
- 身份证号

#### 监控告警

**告警触发条件**:
- 5 分钟内登录失败 > 10 次
- API 错误率 > 5%
- 响应时间 > 3 秒
- 磁盘使用率 > 80%
- 发现安全漏洞

## 依赖管理

### 依赖审查

**引入新依赖前检查**:
- [ ] 是否有已知安全漏洞
- [ ] 最近更新时间（避免废弃项目）
- [ ] 社区活跃度（GitHub stars、issues）
- [ ] 许可证兼容性
- [ ] 是否有替代方案

### 漏洞扫描

**自动扫描**:
- CI/CD 集成扫描（每次 MR）
- 定期扫描（每周）
- Dependabot 自动更新

**扫描工具**:
- Trivy (容器和文件系统)
- pip-audit (Python)
- npm audit (Node.js)
- flutter pub outdated (Flutter)

### 更新策略

| 严重程度 | SLA | 处理方式 |
|---------|-----|---------|
| Critical | 24 小时 | 立即修复，紧急发布 |
| High | 7 天 | 优先修复，下个版本 |
| Medium | 30 天 | 计划修复，常规迭代 |
| Low | 90 天 | 择机修复，技术债务 |

详见: [依赖漏洞扫描文档](./DEPENDENCY_SCANNING.md)

## 合规要求

### GDPR (欧盟通用数据保护条例)

**适用场景**: 处理欧盟用户数据

**关键要求**:
- 数据最小化原则
- 用户同意机制
- 数据可携带权
- 被遗忘权（数据删除）
- 72 小时内报告数据泄露

**实施措施**:
- 隐私政策和用户协议
- Cookie 同意横幅
- 数据导出功能
- 账户删除功能
- 数据泄露响应流程

### 个人信息保护法 (中国)

**适用场景**: 处理中国用户数据

**关键要求**:
- 告知-同意原则
- 数据本地化存储
- 敏感个人信息单独同意
- 个人信息影响评估

**实施措施**:
- 数据存储在中国境内
- 明确的隐私政策
- 敏感权限申请说明
- 定期隐私影响评估
