# 安全应急响应流程

## 概述

本文档定义 DaCong 项目的安全事件应急响应流程，确保在发生安全事件时能够快速、有效地响应和处理。

## 事件分类

### 严重程度定义

| 级别 | 描述 | 响应时间 | 示例 |
|------|------|---------|------|
| P0 - 紧急 | 严重影响生产环境，数据泄露风险 | 立即响应 | 数据库被入侵、严重漏洞被利用 |
| P1 - 高危 | 影响核心功能，潜在安全风险 | 2 小时内 | 高危漏洞发现、认证绕过 |
| P2 - 中危 | 影响部分功能，安全风险可控 | 24 小时内 | 中危漏洞、配置错误 |
| P3 - 低危 | 轻微影响，无直接安全风险 | 7 天内 | 低危漏洞、安全建议 |

### 事件类型

**数据泄露**:
- 数据库泄露
- API 数据泄露
- 日志泄露敏感信息
- 备份文件泄露

**系统入侵**:
- 服务器被入侵
- 账户被盗用
- 权限提升攻击
- 后门植入

**服务中断**:
- DDoS 攻击
- 资源耗尽
- 恶意流量
- 系统崩溃

**漏洞利用**:
- SQL 注入
- XSS 攻击
- CSRF 攻击
- 远程代码执行

**社会工程**:
- 钓鱼攻击
- 账户欺诈
- 内部威胁
- 供应链攻击

## 响应流程

### 阶段 1: 发现和报告（0-15 分钟）

#### 1.1 事件发现

**发现渠道**:
- 监控告警
- 用户报告
- 安全扫描
- 第三方通知
- 内部发现

#### 1.2 初步评估

```bash
# 快速检查清单
- [ ] 确认事件真实性
- [ ] 评估影响范围
- [ ] 确定严重程度
- [ ] 识别受影响系统
```

#### 1.3 事件报告

**报告方式**:
- 邮箱: security@dacong.ai
- 电话: [紧急联系电话]
- GitLab Issues: [Security Label]
- 内部通讯工具

**报告内容**:
```
事件报告模板:

1. 事件概述
   - 发现时间: [YYYY-MM-DD HH:MM:SS]
   - 发现人: [姓名]
   - 事件类型: [数据泄露/系统入侵/服务中断/漏洞利用]

2. 影响范围
   - 受影响系统: [列表]
   - 受影响用户: [数量/范围]
   - 数据泄露: [是/否，类型]

3. 初步分析
   - 可能原因: [描述]
   - 攻击向量: [描述]
   - 当前状态: [进行中/已控制]

4. 紧急程度
   - 严重级别: [P0/P1/P2/P3]
   - 建议响应时间: [立即/2小时/24小时/7天]
```

### 阶段 2: 遏制和隔离（15 分钟 - 2 小时）

#### 2.1 启动应急响应

**P0/P1 事件**:
```bash
# 1. 召集应急响应团队
# 2. 建立应急沟通渠道（专用群组）
# 3. 指定事件协调人
# 4. 开始记录时间线
```

#### 2.2 遏制措施

**立即遏制**（防止扩散）:

```bash
# 选项 1: 隔离受影响系统
# - 断开网络连接
# - 禁用受影响账户
# - 关闭受影响服务

# 选项 2: 限制访问
# - 添加 WAF 规则
# - IP 黑名单
# - 限流规则

# 选项 3: 回滚变更
# - 回滚到安全版本
# - 恢复备份
# - 切换到备用系统
```

**证据保全**:
```bash
# 1. 保存日志
mkdir -p /tmp/incident-$(date +%Y%m%d-%H%M%S)
cp -r /var/log/* /tmp/incident-$(date +%Y%m%d-%H%M%S)/

# 2. 保存系统快照
# - 虚拟机快照
# - 磁盘镜像
# - 内存转储

# 3. 保存网络流量
tcpdump -i eth0 -w /tmp/incident-$(date +%Y%m%d-%H%M%S)/traffic.pcap

# 4. 记录系统状态
ps aux > /tmp/incident-$(date +%Y%m%d-%H%M%S)/processes.txt
netstat -antp > /tmp/incident-$(date +%Y%m%d-%H%M%S)/connections.txt
```

#### 2.3 影响评估

```bash
# 评估清单
- [ ] 哪些系统受影响？
- [ ] 多少用户受影响？
- [ ] 哪些数据可能泄露？
- [ ] 攻击者获得了什么权限？
- [ ] 攻击持续了多久？
- [ ] 是否有数据被篡改或删除？
```

---

### 阶段 3: 根因分析（2-8 小时）

#### 3.1 日志分析

```bash
# 1. 收集相关日志
./scripts/collect_logs.sh --incident-id=INC-20260417-001

# 2. 分析访问日志
grep "suspicious_pattern" /var/log/nginx/access.log

# 3. 分析应用日志
grep "ERROR\|WARN" /var/log/app/*.log

# 4. 分析数据库日志
grep "unauthorized" /var/log/postgresql/*.log
```

#### 3.2 系统分析

```bash
# 1. 检查异常进程
ps aux | grep -v "^root\|^www-data"

# 2. 检查异常网络连接
netstat -antp | grep ESTABLISHED

# 3. 检查文件修改
find /var/www -type f -mtime -1

# 4. 检查用户活动
last -a | head -20
```

#### 3.3 漏洞分析

```bash
# 1. 运行安全扫描
./scripts/security_scan.sh

# 2. 检查依赖漏洞
./scripts/fix_vulnerabilities.sh

# 3. 代码审查
# - 检查最近的代码变更
# - 审查相关代码路径
# - 查找类似漏洞
```
